# superpowers

## 解决什么问题

这是一个**规范写代码流程的 skill**。很多人写代码是这样的：想到哪写到哪，不先想清楚就动手，结果写到一半发现方向错了；改 bug 全靠猜，这里试一下那里试一下，越改越乱。

这个 skill 解决的就是这个问题。它把"写代码"这件事变成一条固定的流水线：**先想清楚要做什么 → 再写详细计划 → 再动手写 → 写完测试 → 最后收尾**。它要解决的本质问题是：AI 常常"像会写代码、但不懂工程流程的实习生"——而这个 skill 就是补上"工程流程"这一课。

## 工作流程

它是一条流水线，每个编码任务都走这几步：

**1. 头脑风暴**：先探索项目、问清楚需求（一次只问一个问题）、给出 2-3 个方案让你选。**没确认方案前，绝不写代码。**

**2. 写计划**：把方案拆成一个一个 2-5 分钟的小任务，每个任务都是"写测试 → 看它失败 → 实现 → 看它通过"。

**3. 子代理开发**：按计划逐条执行，每个小任务都用测试驱动（TDD），做完一个提交一个。

**4. 系统化调试**：遇到 bug 时，先查根因、再分析、再验证，**不瞎改**。

**5. 收尾**：全部测试通过后，给你合并/推送/丢弃几个选项。

## 核心设计原则

这五步背后，有 4 条原则贯穿始终：

| 原则 | 大白话解释 |
|------|-----------|
| **先写测试** | 永远先写测试，亲眼看到它失败，才能确认测试真的有用 |
| **走流程不靠猜** | 每个环节都有明确的判断标准，不凭感觉 |
| **能删就删** | 主动删掉不需要的功能，别堆砌 |
| **看证据不看感觉** | 必须真的跑起来、测试通过，而不是"我觉得应该行" |

## 使用示例

**例子：开发一个新功能**

```
@gateway 用 superpowers skill 实现 给项目加一个用户登录功能
```

它会先问清需求、给你方案，确认后才开始按计划一步步实现，每步都带测试。

**例子：调试一个 bug**

```
@gateway 用 superpowers skill 实现 这个测试失败了帮我修
```

它会先查根因，而不是直接改代码。
